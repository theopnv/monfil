# Frontend

The renderer is a React 19 app. It uses TanStack Router, Tailwind CSS v4, and Untitled UI
on top of React Aria Components.

## Layout

| Folder | Holds |
| --- | --- |
| `src/renderer/routes/` | File-based routes. |
| `src/renderer/components/` | This project's components, in PascalCase files. |
| `src/renderer/components/untitled-ui/` | Vendored Untitled UI, in kebab-case files. |
| `src/renderer/providers/` | React context providers. |
| `src/renderer/styles/` | Tailwind entry point and themes. |

`src/renderer/routeTree.gen.ts` is generated by the TanStack router Vite plugin. Do not
edit it. It regenerates on the next dev run or build.

## Routing

Add a route by adding a file to `src/renderer/routes/`. Nothing else needs to change.

The router uses hash history. Production serves the renderer over `file://`, where
path-based routing cannot resolve a route against the filesystem path. This is why e2e
tests navigate with `window.history.pushState(null, '', '#/settings')` instead of a URL
push.

React Aria links need a bridge to the router. `RouteProvider` supplies it. Any subtree
with Untitled UI links or buttons that navigate must sit below that provider.

## Providers and data

App-wide providers belong in the root route, `src/renderer/routes/__root.tsx`. Providers
that only feed one part of the app belong in `AppShell`, wrapped around the part that
reads them.

Main pushes data to the renderer, and the renderer does not poll. A provider subscribes
with `window.electron.ipcRenderer.on(...)` in a `useEffect` and returns the unsubscribe
function that the call gives back. Components read the result through a hook that throws
when it is used outside its provider. `feeds-provider.tsx` is the model to copy.

Expect data to arrive in pieces. Main sends one message per item, so a provider has to
merge into existing state rather than replace it.

## Styling

`src/renderer/styles/globals.css` is the entry point. It imports Tailwind, then
`theme.css`, then `monfil-theme.css`.

`theme.css` is vendored from Untitled UI. Do not edit it, because it is replaced when
their theme is re-pulled. Put every palette change in `monfil-theme.css`, which loads
after it and wins.

Use the semantic tokens (`bg-primary`, `text-brand-secondary`, `border-secondary`) rather
than raw color values. They resolve for light mode and dark mode on their own.

Dark mode is a `dark-mode` class on `<html>`, set by `ThemeProvider` and declared as a
custom variant in `globals.css`. The theme is read from `localStorage` and follows the
system setting by default.

## Untitled UI

See [doc/untitled-ui.md](untitled-ui.md) for how to add a component, why the vendored
folder has its own tsconfig, and the icon and naming conventions.

## Window chrome

The window uses `titleBarStyle: 'hidden'`. `AppShell` draws the strip that replaces the
title bar, and that strip carries the drag region. An element inside a drag region does
not receive clicks unless it opts back out.
