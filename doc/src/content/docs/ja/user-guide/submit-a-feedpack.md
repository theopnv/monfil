---
title: フィードパックを提出する
description: ほかの Monfil ユーザーと、フィードのまとまりを共有します。
---

フィードパックとは、あるテーマに関するフィードのまとまりです。Monfilでフィードパックを作成し、フィードパックのカタログに提案できます。提出するには GitHub アカウントが必要ですが、すべての手順は GitHub の Web サイトで行えます。

フィードを含む OPML ファイルを提出し、`feedpacks/index.json` を更新してパックを説明します。プルリクエストで、Monfilのメンテナーに変更の確認を依頼します。承認されると、パックがカタログに表示されます。

## 1. Monfilでパックを作成する

1. 左側のレールで **+** を選択し、テーマ用のワークスペースを作成します。フィードのサイドバー上部の **+** を使って、共有したいフィードを追加します。役立つフォルダに分けて入れてください。
2. 各フィードを開きます。コンテンツが公開されていて、テーマに合っているか確認します。重複したフィードや、動かないフィードは削除します。
3. レールでワークスペースのアイコンを右クリックし、**OPMLとしてエクスポート** を選択します。
4. ファイルを、小文字の単語をハイフンでつないだ短い名前で保存します。例: `web-performance.opml`。

OPMLは、Monfilがアプリ間でフィードとフォルダの一覧を移動するために使うファイル形式です。エクスポートすると、そのワークスペースのフィードが保存されます。

## 2. GitHub でプロジェクトのコピーを作成する

1. 必要であれば [GitHub アカウントを作成](https://github.com/signup) します。サインインして、[Monfilのリポジトリ](https://github.com/theopnv/monfil) を開きます。
2. **フォーク** を選び、次に **フォークを作成** を選択します。GitHub があなたのアカウントにコピーを作成します。[GitHub のフォークガイド](https://docs.github.com/en/pull-requests/how-tos/work-with-forks/fork-a-repo) に、これらのボタンの画像があります。
3. フォークで、ファイル一覧の上にあるブランチメニューを開きます。最初は **main** と表示されています。`add-web-performance-pack` のような名前を入力し、**ブランチを作成** を選択します。ブランチには、提出する変更が入ります。両方のファイル変更で、このブランチを選択したままにしてください。

## 3. OPML ファイルをアップロードする

1. フォークで `feedpacks` フォルダを開きます。
2. **ファイルを追加** を選び、次に **ファイルをアップロード** を選択します。エクスポートした OPML ファイルを選びます。
3. 作成したブランチで変更を保存します。GitHub のボタンには **変更をコミット** または **変更を提案** と表示される場合があります。コミットは、コピーへの変更を保存するものです。

## 4. カタログにパックを説明する

1. フォークのまま、同じブランチにいます。`feedpacks/index.json` を開き、鉛筆アイコンを選んで編集します。
2. `packs` リストに、オブジェクトを1つ追加します。自分のオブジェクトと、その前のオブジェクトの間にカンマを入れます。次の例を参考にしてください:

```json
{
  "slug": "web-performance",
  "title": "Web Performance",
  "description": "Browser performance, metrics, tooling, and field research.",
  "tags": ["web", "performance", "browsers"],
  "curator": "Your name or handle",
  "sourceCount": 12,
  "updatedAt": "2026-09-30",
  "opml": "web-performance.opml"
}
```

例の値は、あなたの値に置き換えてください。`slug` は既存のパックの中で一意にし、`opml` はファイル名と完全に一致させます。`sourceCount` はフィードの数です。フォルダは含めません。`updatedAt` は、ソースを最後に確認した日付で、`YYYY-MM-DD` 形式で書きます。短い説明と、小文字の検索タグを数個使います。ルートの `version` の値は、そのままにします。

この変更は、OPML ファイルと同じブランチに保存します。

## 5. レビューを依頼する

1. [元のMonfilリポジトリ](https://github.com/theopnv/monfil) に戻ります。**Pull requests** を選び、次に **New pull request** を選択します。
2. **フォーク間で比較** を選択します。ベースリポジトリを `theopnv/monfil`、ベースブランチを `main` に設定します。**head fork** をあなたのコピーに、**compare branch** を作成したブランチに設定します。[GitHub のプルリクエストガイド](https://docs.github.com/en/pull-requests/how-tos/create-pull-requests/creating-a-pull-request-from-a-fork) に、この画面が示されています。
3. **変更されたファイル** を確認します。OPML ファイルと `feedpacks/index.json` への編集が表示されるはずです。
4. リクエストに分かりやすいタイトルを付けます。説明欄には、パックの内容、フィードの選び方、ソースに説明が必要かどうかを書きます。**プルリクエストを作成** を選択します。

GitHub は、OPML ファイルが存在することと、`sourceCount` がフィードの数と一致することを確認するチェックを実行します。メンテナーは、ソース、テーマとの適合性、カタログの詳細を確認します。プルリクエストで質問に返信できます。変更が必要な場合は、同じブランチを更新できます。

パックが承認される前に、[コントリビューターライセンス契約](https://github.com/theopnv/monfil/blob/main/CLA.md) に署名する必要があります。CLA Assistant がプルリクエストにリンクを追加します。そのリンクから署名してください。

## 自分でOPMLファイルを作る場合

OPML 2.0 を使います。フォルダごとに `<outline>` を作り、各フィードはフォルダの中に入れます。各フィードには、タイトル、対応している `type`、`xmlUrl` が必要です。[既存のフィードパック](https://github.com/theopnv/monfil/tree/main/feedpacks) を例として使えます。

プロジェクトをローカルで作業する場合は、提出前に `npm install` を実行してから、`npm run check:feedpacks` を実行してください。このコマンドは、カタログのファイル名とソース数を確認します。URL が動くこと、内容がパックに合うことは、自分でフィードを開いて確認してください。
